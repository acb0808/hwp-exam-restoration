# 페이지 구조 계약 v1

페이지 담당 서브에이전트는 원본 한 페이지를 보고 JSON 하나를 만든다. 전체 문항을 읽는 순서로 이어 쓰는 OCR 문자열이 아니라 원본의 실제 위치를 기록한다. 메인은 내용을 재작성하거나 줄바꿈·문항 배분을 고치지 않고 JSON을 검사·취합한다. [합성 예시](../examples/page-001.json)는 왼쪽 3문항·오른쪽 2문항을 나타내는 계약 예시이며 실제 원본과의 일치 증거가 아니다.

`scripts/restoration_contract.py`의 `validate_page(page)`가 아래 계약을 검사한다. 표준 라이브러리만 사용하며 입력을 수정하지 않는다. 알 수 없는 키, 누락 키, 지원하지 않는 값은 `ValueError`로 실패한다. 선택 키는 없다. 모든 필드는 명시해야 한다.

## 페이지

| 키 | 값 |
|---|---|
| `version` | 정수 `1` |
| `source_sha256` | 원본의 SHA-256, 64자리 16진수. 준비 단계가 제공한 값을 그대로 사용 |
| `page_number` | 1부터 시작하는 정수 |
| `size_mm` | `[너비, 높이]`, 양수 |
| `assignment_id` | 준비/위임 단계가 부여한 비어 있지 않은 문자열 |
| `worker_id` | 실제 담당 에이전트 식별자 문자열 |
| `issues` | 미해결 문제 문자열 배열. 미해결 내용은 숨기지 않고 기록. **생산용 승인에는 빈 배열이어야 함** |
| `regions` | 비어 있지 않은 단/영역 배열 |
| `questions` | 비어 있지 않은 문항 배열 |
| `blocks` | 비어 있지 않은 실제 출력 요소 배열 |

숫자는 유한해야 하며 `true`/`false`는 숫자로 취급하지 않는다. 길이·좌표 단위는 mm, 글자 크기는 pt다. 모든 `bbox_mm`은 페이지 왼쪽 위를 원점으로 하는 절대좌표 `[x, y, 너비, 높이]`다. 너비·높이는 양수, 좌표는 0 이상이며 전체 영역은 페이지 안에 있어야 한다. region·question·block의 `id`는 페이지 전체에서 중복할 수 없다.

## 영역과 문항

영역은 정확히 `id`, `bbox_mm`, `question_ids`를 갖는다. `question_ids`는 원본 해당 단의 문항 ID를 읽기 순서대로 기록한다. 문항은 정확히 `id`, `region_id`, `bbox_mm`을 갖는다. 문항 영역은 지정한 단/영역에 완전히 포함되어야 한다.

`questions` 배열에서 해당 `region_id`의 문항을 추린 결과가 `question_ids`와 순서까지 같아야 한다. 누락·중복·다른 단으로 옮긴 매핑은 거부한다. 왼쪽 3문항·오른쪽 2문항이면 3:2 그대로 기록하고, 빈 풀이 영역은 문항 bbox 안에 남긴다. 빈 공간을 줄이기 위해 뒤 문항을 당기지 않는다.

## 출력 요소

모든 block은 정확히 공통 키 `id`, `question_id`, `kind`, `bbox_mm`과 아래 종류별 키를 갖는다. 문항에 속하는 요소는 `question_id`를 지정하며 해당 문항 bbox 안에 완전히 들어가야 한다. 제목·쪽번호·중앙 구분선처럼 문항 밖 요소는 `question_id: null`로 기록한다. 모든 문항에는 text/line/equation/image 중 하나 이상의 내용 요소가 있어야 한다.

| `kind` | 추가 필수 키 | 규칙 |
|---|---|---|
| `text` | `text`, `font_pt`, `font_family` | 수식 없는 원본 한 줄. `$`, LaTeX 명령, 개행, 탭 금지 |
| `line` | `runs`, `font_pt`, `font_family` | 한 원본 줄의 본문과 수식. 순서대로 `{kind: text, text: ...}` 또는 `{kind: equation, latex: ...}` 배열 |
| `equation` | `latex`, `font_pt` | `$` 구분자와 개행 없는 LaTeX. 본문에 끼지 않는 독립 수식/선지에만 사용 |
| `image` | `path`, `sha256`, `role` | `role: "figure"`만 허용. 반드시 문항 소속. 원본의 작은 도형·그래프만 사용 |
| `box` | `title`, `title_bbox_mm`, `stroke_mm`, `font_pt`, `font_family` | 사각 테두리와 제목. 본문·수식은 별도 block으로 box 안 위치에 기록 |
| `rule` | `stroke_mm` | 가로/세로 직선. bbox로 위치와 방향을 표현 |

`font_pt`와 `stroke_mm`은 양수, `font_family`는 실제 사용할 폰트 이름이다. 본문은 빈 문자열을 허용하지 않는다. box 제목이 없으면 `title: ""`, `title_bbox_mm: null`이다. 제목이 있으면 양수 크기의 제목 bbox가 페이지 안에 있어야 하며 부모 box 영역과 교차해야 한다. 원본처럼 위 테두리에 걸치거나 상자 안에 있는 제목 모두 가능하다. 제목 bbox는 테두리 밖으로 일부 나갈 수 있다.

이미지 `sha256`은 64자리 16진수다. 이미지가 페이지 면적의 80% 이상이면 전체 페이지를 그림으로 대신한 것으로 보고 거부한다. 이 검사만으로 이미지 안에 본문이 포함되지 않았음을 증명하지는 못한다. 에이전트는 문항 전체·보기 전체·텍스트·수식을 이미지로 덮어 넣지 않는다. 이미지 파일 접근과 해시의 실물 일치는 컴파일 단계에서 추가 검사한다.

## 원본 보존과 지원 한계

각 원본 줄/선지 셀은 line/runs로 묶고 그 전체 위치를 기록한다. 인라인 수식을 본문과 따로 위치 지정하지 않는다. 그림과 테두리는 독립 위치를 기록한다. 문자열 길이를 이용한 자동 줄바꿈·선지 열 수 결정·문항 균등 분배는 하지 않는다. 렌더러가 넘침을 해결하려고 축소하거나 다음 단으로 보내는 것도 허용하지 않는다.

현재 v1에는 색상, 굵기, 기울임, 글자 간격, 회전, 임의 도형, 표 병합 등의 속성이 없다. 원본에서 해당 속성이 필요하면 조용히 버리거나 비슷한 흑백으로 바꾸지 말고 `issues`에 적어 **지원 구현 또는 사용자 결정 전까지 생산용 완료를 막는다**. 표는 지원 범위 안에서 개별 셀 테두리와 고정 텍스트 요소로 표현할 수 있지만 복잡한 병합·다중선 등 미지원 특성을 숨기면 안 된다.

계약 통과는 원본 전사 정확성, 실제 서브에이전트 실행, 한글의 최종 렌더링 일치를 증명하지 않는다. 위임 기록 검사, 변환 실패 검사, 실제 한글 출력 검증과 원본 전 페이지 대조가 별도로 필요하다. 임의의 `worker_id` 문자열이나 합성 예시의 해시는 위임·원본 증거가 아니다.

본문·수식 run의 정확한 제약과 네이티브 크기 검사는 [혼합 줄 계약](inline-equations.md)을 따른다. runs는 비어 있지 않아야 하며 종류별 키만 허용한다. text에는 개행/탭/LaTeX가 없어야 하며 equation.latex에는 달러 구분자/개행이 없어야 한다.
