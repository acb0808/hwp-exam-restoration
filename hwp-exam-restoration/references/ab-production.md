# 승인 후 A의 단독 제작

이 안내는 메인이 내용 승인을 완료하고 제작을 배정한 **기존 A만** 읽는다. B는 제작에 참여하지 않는다. task의 확정 전사 경로를 내용의 기준으로 사용하고 본문·수식·선지·배점·도형 ID를 임의 변경하지 않는다. 원본 오독이 발견되면 메인에게 보고해 전사 재제출·비교·판정을 다시 거친다.

## 배치

layout.json은 `schema:"restoration-layout/1"`, `regions`, `questions`만 갖는다. regions는 단별 `id`·좌표이며 `question_ids`는 선택이다. questions는 원본 순서의 `id`, `region_id`, 좌표만 기록한다. content·issues·글꼴·배정 해시를 복사하지 않는다.

좌표는 `bbox_mm:[x,y,너비,높이]` 또는 `bbox_px:[x,y,너비,높이]`와 `coordinate_space:"page"`의 조합이다. 원본 전체 이미지의 실제 픽셀 크기를 기준으로 관찰한 **단·문항 전체 범위만 한 번** 기록한다. 축소 표시 크기나 이미지 전체 경계를 실제 문항 경계로 쓰지 않는다. 줄별 측정·좌표 변환 코드·전 문항 crop은 필요 없다. 컴파일러가 단위 변환·최종 셀 배치를 담당한다.

```json
{
  "schema":"restoration-layout/1",
  "regions":[{"id":"left","bbox_px":[100,200,800,2200],"coordinate_space":"page"}],
  "questions":[{"id":"q1","region_id":"left","bbox_px":[110,210,750,300],"coordinate_space":"page"}]
}
```

예제 좌표·문항 수는 실제 원본 값으로 대체한다. 승인된 모든 문항을 같은 좌우 단과 순서로 기록한다. 글자 축소·문항 이동으로 넘침을 숨기지 않는다.

## 도형이 있을 때만

승인된 figure_ref 목록에 있는 도형만 한 번 제작한다. [TikZ 도형 규칙](tikz-exam.md)을 읽되 **그 문서의 모든 명령은 메인에게 요청한다**. 이 담당자는 파일 읽기·작성·보고만 가능하다. 원본에서 점·선·곡선·라벨·표식을 관찰해 완결 TeX와 figures-spec.json을 작성한다. 스캔 crop 삽입, 원본에 없는 보조선·각 표시·라벨 추가는 금지한다.

필요한 도형이 전체 쪽에서 충분히 보이지 않으면 해당 범위만 메인에게 요청한다. 이미 제공된 원본 확대를 재사용하고 crop용 Python 코드는 만들지 않는다. 같은 쪽의 도형 소스를 작성해 한 목록으로 메인에게 전달한다. figures-spec 항목은 `id`(승인된 figure_ref), `question_id`, 실제 TeX 절대 경로인 `source`, 원본과 출력 문항 폭을 고려한 `width_mm`이다.

메인이 반환한 실제 PNG와 원본을 열어 geometry·labels·marks·source_comparison을 대조한다. 생성된 review 파일에서 status·checks·issues만 실제 판정으로 갱신하고 경로를 보고한다. 해시·배정 정보·높이를 다시 만들지 않는다. 미확인·실패 상태를 통과로 바꾸지 않는다. 도형이 바뀌면 다시 렌더·대조해야 한다. 성공한 환경·수식별 시험을 반복하지 않는다.

## 제출과 최종 대조

layout와 필요한 제작·검수 파일 경로를 한 번 보고한다. 메인이 조합·수식 검사·수락·출력을 실행한다. 반환된 오류는 해당 문항·위치만 원본으로 확인해 수정하고 본문 변경은 재판정을 요청한다.

최종 검수 요청이 오면 실제 원본과 출력 PDF를 대조한다. 누락·오독·선지·배점·도형·잘림·겹침을 확인하고 관찰한 결과만 기록한다. JSON 검사나 도형 렌더 성공으로 페이지 검수를 대신하지 않는다. 수정되면 재출력까지 확인해야 완료다.
