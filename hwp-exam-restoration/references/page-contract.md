# 페이지 OCR 입력 형식 (v2)

새 작업은 [간결한 작성 형식](compact-draft.md)을 사용한다. 이 문서는 기존 version=2 결과를 직접 수정하거나 선택 속성을 확인할 때만 읽는다.

페이지 담당자는 [2단 예제](../examples/ocr-page.json)를 바탕으로 **배정된 한 쪽의 JSON 하나**를 만든다. 예제는 형식 설명용 합성 데이터다. 문장·문항 수·좌표를 원본 대신 복사하지 않는다. 스킬 코드나 한글 XML을 읽을 필요는 없다.

## 페이지와 문항

`result_path`에 생성된 JSON 초안에 원본에서 관찰한 내용을 채운다. `input.json`은 안내이며 제출물이 아니다. `page_metadata`와 `font_family`, `font_pt`는 이미 준비되어 있다. 저장 후 입력 파일의 `validation_command`를 실행하면 모든 수식의 변환 오류·위치·hint를 함께 받는다. 내부 함수를 import하거나 수식마다 실험용 코드를 만들지 않는다. 검증은 원본 대조를 대신하지 않는다.

| 키 | 입력할 값 |
|---|---|
| `version` | `2` |
| `source_sha256`, `page_number`, `size_mm`, `assignment_id`, `worker_id` | 메인이 전달한 원본·배정 정보 그대로 |
| `issues` | 판독 불가·미해결 사항. 없으면 `[]`. 미해결 상태는 수락되지 않는다. |
| `regions` | 좌/우 단 각각의 `id`, `bbox_mm`, 읽는 순서의 `question_ids` |
| `questions` | 문항 배열. 각 문항은 `id`, `region_id`, `bbox_mm`, `font_pt`, `font_family`, `content` |
| `blocks` | 기본 템플릿에서는 `[]`. 상단 표·머리글을 별도로 전사하지 않는다. |

`bbox_mm`은 원본 페이지 왼쪽 위 기준 `[x, y, 너비, 높이]`(mm)다. **단과 문항 전체에만** 기록한다. 문항은 소속 단 안에 있어야 하고 `questions`의 각 단별 순서는 `question_ids`와 같아야 한다. 좌표는 원본의 문항 영역 기록이며 최종 셀 위치·병합은 Python이 결정한다. 내부 줄마다 위치를 추정하지 않는다.

문항의 `font_pt`(pt), `font_family`는 출력에 사용할 글자 크기와 글꼴이다. 작업에서 정한 공통값을 사용하고 넘침을 숨기려고 줄이지 않는다. 모든 ID는 페이지 안에서 중복되지 않게 만든다.

## 문항 내용

`content`에 원본 순서대로 넣는다. 자세한 선택 속성이 필요할 때만 [내용 필드](question-flow.md)를 읽는다.

- **본문:** `{"id":"q1-body","kind":"paragraph","runs":[...]}`. runs에 `{"kind":"text","text":"1. 값은 "}`와 `{"kind":"equation","latex":"\\frac{1}{2}"}`를 섞는다. 수식은 `$` 없이 기록하며 JSON의 역슬래시는 `\\`로 쓴다. 필수 줄바꿈은 `{"kind":"break"}`다.
- **보기/조건:** `{"id":"q1-box","kind":"box","title":"〈보 기〉","content":[본문 문단들]}`. 제목 없는 박스는 `title:""`. 선·표·제목 배치는 Python이 만든다.
- **선지:** `{"id":"q1-choices","kind":"choices","columns":3,"rows":[[첫째선지runs,둘째선지runs,셋째선지runs],...]}`. 원본의 행 배분을 기록한다.
- **그림:** 소속 paragraph의 `figure`에 연결한다. 그림이 있을 때만 [TikZ 절차](tikz-exam.md)를 따라 소스·렌더 결과·대조 기록을 제출한다.

### 반복 오류를 피하는 수식 입력

- 집합 조건 구분선은 `A=\{x|x>0\}`처럼 `|`를 사용한다. `\mid`는 미지원이다. 나눗셈 관계 등 의미가 다른 표기는 임의로 바꾸지 말고 미지원 사항으로 보고한다.
- `\frac{a}{b}`, `\sqrt{x}`, `\overline{AB}`, `\angle ABC`, `x\in A`, `\text{자연수}`를 지원한다. JSON 문자열에서는 각 역슬래시를 이스케이프한다. 본문의 한국어 설명은 인접한 text run이 기본이며 수식 내부 문자는 올바른 중괄호를 유지한다.
- 그림만 있는 paragraph는 `"runs":[]`로 만든다. `"latex":""`인 빈 수식을 넣지 않는다.
- 위 예는 전체 문법 목록이 아니다. 전체 페이지를 한 번 검증하고 반환된 위치·hint를 따른다. 근거 없이 수식 일부를 지우거나 원본 의미를 바꿔 통과시키지 않는다.

그림은 본문 문단 뒤의 별도 그림 문단에 두는 것이 기본이다. 본문 문단에 `figure`를 연결해도 Python이 본문 다음 문단으로 분리하고 높이를 확보한다. `after_mm`으로 그림 높이를 직접 계산할 필요가 없다. 그림을 본문의 중간에 둬야 하면 원본 순서에 맞춰 본문 앞/뒤 문단 사이에 그림 전용 paragraph를 둔다. 보기는 명시한 `after_mm`이 없을 때 기본 2mm 뒤 간격을 갖는다.

본문을 줄마다 paragraph로 쪼개거나 문항마다 조판 스크립트를 만들지 않는다. 답·풀이를 추가하거나 다음 쪽/단으로 문항을 옮기지 않는다. 메인은 JSON 내용을 고치지 않으므로 오류를 전달받으면 담당자가 수정한다.

옛 작업의 version=1 입력을 유지보수할 때만 [이전 계약](legacy-page-contract.md)을 참고한다. 새 OCR에는 사용하지 않는다.
