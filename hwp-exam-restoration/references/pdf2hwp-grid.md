# pdf2HWP 원본 표와 6행×2열 병합

## 기준 자산

이 양식은 현재 저장된 기본값이다. 사용자가 다른 템플릿을 명시하지 않으면 `restore.py build`의 `--template-dir` 생략 시에도 적용된다. 학교명·연도·시험명은 `--template-fields`, 문서 제목은 `--title`로 전달한다. 생략 때문에 템플릿 없는 1×1 문항 표로 되돌아가는 경로는 사용하지 않는다.

런타임 입력은 **스킬 내부의 `assets/templates/pdf2hwp-grid/source.hwpx`**다. `pdf2HWP/sample/template.hwp`는 이 자산의 출처 설명일 뿐 찾거나 열어야 할 외부 파일이 아니다. 이미 변환된 실제 템플릿과 스타일을 배포물에 포함하며 `profile.json`의 해시로 검사한다.

병합 로직은 이 스킬의 `scripts/pdf2hwp_grid.py`에 포함되어 있다. 외부 `nogada.py`를 읽거나 실행할 필요가 없다. 실제 템플릿은 첫 쪽에 상단 표와 본문 6행×2열이 결합돼 있고(물리 구조 10행×5열), 다음 쪽은 6행×2열이다. 본문 셀의 `#M1#`~`#M24#`가 내용 자리다. 외부 참고 스크립트를 직접 실행하지 않는다. 소유권 없는 한글 생성·키 입력 이동·선지를 흰색으로 만드는 예전 로직은 사용하지 않는다.

## 배치 계약

페이지 담당자는 수락 가능한 v2 JSON으로 문항 내용과 좌우 단 소속, 순서를 제공한다. 메인은 문항을 다시 쓰거나 줄마다 x/y를 설계하지 않는다. Python이 각 단의 문항 수와 순서로 셀 병합 계획을 만든다.

| 한 단의 문항 수 | 6개 기본 행 병합 | 문항 영역 |
| --- | --- | --- |
| 1 | 6 | 전체 높이 |
| 2 | 3 + 3 | 위/아래 두 셀 |
| 3 | 2 + 2 + 2 | 위/중간/아래 세 셀 |
| 4 | 1 + 2 + 1 + 2 | 여섯 행 기준 근사 분할 |
| 5 | 1 + 1 + 1 + 1 + 2 | 여섯 행 기준 근사 분할 |
| 6 | 1 + 1 + 1 + 1 + 1 + 1 | 병합 없이 여섯 셀 |

왼쪽 3문항·오른쪽 2문항이면 같은 페이지에서 각각 2+2+2와 3+3으로 병합한다. 양쪽 문항 수가 같지 않아도 번호를 재배분하지 않는다. 4/5개는 균등 높이가 아니므로 균등하다고 보고하지 않는다. 한 단이 비어 있거나 6개를 넘으면 현재 경로는 실패한다. 문항을 임의로 다른 쪽에 보내지 않는다.

병합 뒤 양쪽 모두 비게 된 물리 행은 한글 호환을 위해 정리한다. 예를 들어 양쪽 3문항은 실제 표에서 3개 문항 행으로 정규화되지만, receipt의 `base_rows:6`과 `merges`에는 2행씩 병합한 논리 계획이 남는다. 원본 셀 높이의 합, 상단선·하단선, 영역 테두리 주소도 함께 보존한다.

각 문항은 병합된 셀의 `subList` 안에 일반 문단·편집 가능한 인라인 수식·탭 선지로 직접 들어간다. **문항마다 표를 또 넣지 않는다.** 보기/조건 박스 전체에만 의미상 필요한 내부 표를 둔다. 빈 문단/줄바꿈 개수로 번호 위치나 풀이 공간을 맞추지 않는다. 같은 문단 안의 내용상 필요한 줄바꿈은 허용한다.

사용자가 셀 병합 배치를 선택했으므로 기존 스캔의 쪽·단·문항 순서는 보존하되 문항 시작 y좌표는 이 템플릿의 셀 경계를 따른다. 원본 스캔의 문항 간 간격까지 복제한 결과라고 하지 않는다.

## 실행

fields 파일 예:

```json
{"school":"예시고등학교","year":"2025","exam_title":"고1-2 중간고사"}
```

```text
python <SKILL_DIR>/scripts/restore.py build <accepted-job> <exam.hwpx> --template-dir <SKILL_DIR>/assets/templates/pdf2hwp-grid --template-fields <fields.json> --title "2025년 예시고 1-2 중간고사"
python <SKILL_DIR>/scripts/restore.py native <accepted-job> <exam.build.json> <empty-native-output-directory>
```

상단의 `{학교이름}`, `{년도}`, `{시험지제목}`만 치환한다. 이전 템플릿의 파란 칸이나 별도 제목을 추가하지 않는다. 실제 원본 문항 셀 스타일인 한컴 윤고딕 720 8pt와 160% 문단, 인라인 수식 8pt를 사용한다. 내용 넘침을 숨기기 위해 추가로 축소하지 않는다.

## 검증

- `page_grid`는 페이지당 실제 표 하나, `question_cell`은 표 ID·셀 주소·논리/물리 rowspan·가용 폭/높이와 연결된다. `logical_box`만 중첩을 허용한다.
- 병합 셀의 테두리는 첫 셀의 상단/좌우와 마지막 셀의 하단을 결합한다. 마지막 셀의 테두리만 복사하면 다음 쪽 상단선이 사라진다.
- 한글에서 재열기·원본 쪽수·표/셀 높이·수식 폭·rowspan 유지·예상 외 중첩 표를 검사한다. 파일 내 `#M...#`나 상단 placeholder가 남으면 실패다.
- 페이지 담당자는 최종 PDF 해시와 함께 모든 문항/수식/그림/선지, 번호의 셀 소속, 원본 상단·중앙·하단선을 비교한다. 학교명·시험지 제목 치환 외에 원본 상단 셀 구조·서식이 유지됐는지도 별도 검사한다.
- 기존 판독 보류는 유지한다. 단순 저장 성공, 구조 통과 또는 셀 높이 통과만으로 전 페이지 시각 검수를 대신하지 않는다.
