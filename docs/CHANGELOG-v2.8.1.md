# v2.8.1 변경 내용

v2.8.0 이후의 변경입니다. 도형의 각도 표시를 바꿨습니다: 각도 값의 자리와 글자 크기, 값을 각 밖으로 빼는 화살표, 각 안의 점·× 표식, 변 위의 등변 표식. 검수에는 도형 안의 차이가 수정 회차를 열지 못하게 하는 검사 하나를 더했습니다. 읽기, 수식, 조판, 정답표는 v2.8.0과 같습니다.

수치는 모두 실제로 잰 값입니다. 2절의 값은 이미 납품된 도형의 TikZ 원고를 두 버전으로 다시 그려서 잰 것이라 모델의 실행 간 편차가 섞이지 않습니다.

## 1. 무엇이 바뀌었나

| 영역 | 바뀐 점 |
|---|---|
| 각도 값의 자리 | 값이 자기 각의 호 바로 안쪽에 놓입니다. 걸친 라벨을 옮기는 단계도 각도 값을 자기 호에서 2.5 mm 넘게 떼거나, 다른 각의 표시 쪽으로 붙이거나, 선 위에 올리지 않습니다 |
| 글자 크기 | 각 안에 자리가 모자라면 그 그림의 각도 값을 0.92배, 0.85배까지 줄입니다. 점 이름(A, B, C)은 줄이지 않습니다 |
| 화살표 | 0.85배로도 자리가 없으면 값을 각 밖에 두고 굽은 화살표로 호를 가리킵니다. 원본이 화살표로 뺀 값은 제작자가 `\ExamAngle[arrow]{A}{B}{C}{$68^\circ$}`로 지정할 수 있습니다 |
| 겹친 각 | 한 꼭짓점에서 큰 각이 작은 각을 품으면 호를 안팎으로 나누고, 큰 각의 값은 작은 각이 비워 둔 쪽에 둡니다. 전에는 두 값이 같은 자리에 겹쳐 찍혔습니다 |
| 호 크기 | 각을 이루는 변의 인쇄 길이에 맞춥니다(보통 반지름 2.0 ~ 3.8 mm) |
| 점·× 표식 | 호 크기에 맞춰 작아집니다(점 지름 1.55 mm → 0.6 ~ 1.1 mm). 한 그림 안의 표식은 크기가 같습니다. 좁은 각에서는 양쪽 선에 닿지 않도록 꼭짓점에서 더 떨어진 곳에 찍힙니다. 제작자는 `\ExamAngle[draw=none]{A}{B}{C}{$\bullet$}`처럼 표식만 적으면 되고, 자리 옵션(`angle eccentricity`)은 적지 않아도 됩니다 |
| 등변 표식 | 길이를 변 길이에 맞추고(1.3 ~ 1.7 mm), 두 줄·세 줄의 간격을 길이의 0.4배로 좁혔습니다(0.78 mm → 0.5 ~ 0.7 mm). 한 그림 안에서는 크기가 같습니다 |
| 제작 규칙 | 호 크기, 값의 자리, 글자 크기를 엔진이 정하므로 제작자가 `angle radius`를 적지 않습니다. 직접 적은 값이 있으면 그대로 따릅니다. 제작자가 받는 도형 규칙의 길이는 v2.8.0과 거의 같아(17바이트 늘어남) 한 번의 응답에 그대로 들어갑니다 |
| 검수 | 출력에 그려져 있는 도형 안의 차이(빠진 선, 표식 등)는 검수자가 `누락:`이나 `오독:`으로 적어도 `도형:` 검수 노트로만 남고 수정 회차를 열지 않습니다. 도형이 출력에 없는 경우와 본문·선지·정답 지적은 전과 같이 수정 대상입니다. 도형이 그려졌는지는 검수자의 말이 아니라 작업 기록에서 확인합니다 |

## 2. 측정

**납품된 도형을 두 버전으로 다시 그린 결과 (모델 호출 없음)**

고치면서 계속 본 그림과 한 번도 보지 않은 그림을 나눠 적습니다. 새 시험지에서 기대할 수 있는 값은 오른쪽 열입니다.

| | 고치면서 본 그림 (49개, 각도 값 82개) | 처음 본 그림 (26개, 각도 값 31개) |
|---|---|---|
| 자기 호에서 3 mm 넘게 떨어진 값 | 38 → 13 | 11 → 3 |
| 다른 각의 표시에 닿은 값 | 4 → 0 | 1 → 1 |
| 호까지 가장 먼 값 | 10.9 mm → 5.9 mm | 7.2 mm → 3.9 mm |
| 선·표식에 걸린 라벨 | 35 → 23 | 8 → 8 |
| 엔진이 화살표로 뺀 값 | 12 | 6 |

- 처음 본 그림에서 선에 걸린 라벨 수는 줄지 않았습니다. 좋아진 것은 값이 자기 각에 붙는 정도입니다.
- 처음 본 그림에서 원본이 화살표로 뺀 값은 10개였습니다. 엔진은 그중 5개를 화살표로 뺐고, 5개는 각 안에 자리가 있어 안에 두었으며, 원본이 안에 둔 값 1개를 화살표로 뺐습니다. 원본과 똑같이 하려면 제작자가 `[arrow]`를 적어야 합니다.
- 점·× 표식의 자리는 처음 본 그림 가운데 두 쪽을 보고 고쳤습니다. 그 뒤 다시 그렸을 때 표식이 없는 그림 29개는 한 픽셀도 달라지지 않았습니다.
- 각도 값의 글자 크기는 인쇄된 교재를 재서 정했습니다. 교재의 각도 숫자는 높이 2.1 mm, 이전 출력은 2.4 mm였습니다.

**전체 복원 한 번 (OpenCode, 중학교 시험지 6쪽, 도형 22개, 정답표 포함)**

| | v2.8.0 | v2.8.1 첫 실행 | v2.8.1 둘째 실행 |
|---|---:|---:|---:|
| 시간 | 29.9분 | 29.1분 | 39.0분 |
| 가중 토큰 | 316만 | 319만 | 377만 |
| 전체 턴 | 148 | 136 | 161 |
| OpenCode 비용 | $0.153 | $0.162 | $0.192 |

- 세 실행 모두 6쪽과 정답표가 검수를 통과했고, 도형 렌더가 제한 시간을 넘긴 일은 없었습니다.
- 배포본으로 잰 것은 둘째 실행 한 번이고, v2.8.0보다 가중 토큰이 19% 많고 9분 길었습니다. 늘어난 몫은 6쪽 하나에서 나왔습니다. 6쪽 제작자가 각도 표시와 무관한 도형 하나(두 직선의 교점 계산)를 여러 번 고쳤고 재시도 작업자가 한 번 더 붙었습니다. 6쪽의 가중 토큰은 세 실행 순서대로 62만, 30만, 135만이고, 6쪽을 뺀 나머지는 255만, 289만, 242만입니다. 같은 교점 오류는 v2.8.0 실행에도 있었습니다.
- 그래서 이번 변경이 비용을 바꾸지 않는다고 보지만, 한 번씩의 실행으로 확인된 것은 아닙니다.
- 첫 실행은 최종본 직전 빌드, 둘째 실행은 배포본으로 돌렸습니다. 첫 실행에서 제작자가 점 표식을 자리 옵션 없이 적어 점이 크게 찍혔고, 그것을 엔진에서 고친 것이 배포본입니다. 둘째 실행에서는 점이 원본 크기로 꼭짓점 옆에 찍혔습니다.
- 여기서 배포본은 도형 쪽이 배포본과 같은 빌드입니다. 1절의 검수 검사는 이 실행들 뒤에 더했고, 테스트와 지난 작업 기록에 대입하는 것으로만 확인했습니다.
- 두 실행 모두 제작자가 `angle radius`를 직접 적은 도형은 22개 중 0개였습니다.
- 가중 토큰은 `새 입력 + 0.1 × 캐시 + 5 × (출력 + 추론)`입니다.

## 3. 해결한 문제

- **각도 값이 자기 각에서 멀리 떨어져 다른 각의 값처럼 보임.** 값을 호 안쪽에 두고, 옮길 때도 자기 호 근처를 벗어나지 않게 했습니다.
- **좁은 각에 값이 들어가지 않아 선 위에 찍힘.** 먼저 줄이고, 그래도 안 되면 화살표로 뺍니다.
- **한 꼭짓점의 두 각도 값이 겹쳐 찍힘.** 호와 값을 안팎으로 나눕니다.
- **각 안의 점 표식이 원본보다 두 배쯤 큼.** 호 크기에 맞춰 줄였습니다. 좁은 각에서 두 점이 한 덩어리로 붙던 것도 떨어집니다.
- **두 줄 등변 표식의 간격이 원본보다 넓음.** 길이에 맞춰 좁혔습니다.
- **도형 안의 차이 하나로 수정 회차가 열림.** 역할 정의에는 도형 차이를 노트로만 남기라고 적혀 있지만, 이전 버전의 역할 정의로 시작된 검수자가 도형의 빠진 선 하나를 `누락:`으로 적자 재빌드와 두 번째 검수가 돌았습니다(Antigravity 실행 한 번에서 확인). 이제 엔진이 태그와 무관하게 노트로 돌립니다.

## 4. 설치와 호환

- 스킬 폴더 전체를 v2.8.1로 교체하고 `hwp-restoration` MCP를 다시 연결하세요. 절차는 [설치 안내](../AGENT_INSTALL.md)의 “이전 버전에서 업데이트할 때”에 있습니다. 첫 `hwp_prepare` 응답의 `runtime_version`이 `2.8.1`이어야 합니다.
- v2.8.0에서 올 때 새로 설치할 프로그램이나 Python 패키지는 없습니다. MCP 도구 11개와 서브에이전트 역할 정의의 내용도 그대로입니다. 기존 `.mcp-venv`를 그대로 씁니다. Antigravity에서는 설치 안내대로 `scripts/install_reader_agent.py`를 제작자, 검수자 한 번씩 다시 실행하세요.
- 바뀐 파일은 `assets/tikz/exam-marks.tex`, `scripts/restoration_labels.py`, `references/tikz-rules.md`, `scripts/restoration_single.py`(검수 판정과 버전), `tests/test_review_notes.py`와 버전을 적은 문서 두 개입니다.
- 같은 TikZ 원고라도 출력이 달라지는 곳: 각도 값의 자리와 크기, 호 반지름, 점·× 표식의 크기와 자리, 등변 표식의 간격. 이전 작업 폴더의 도형을 다시 렌더하면 이 부분이 달라집니다.

## 5. 알려진 한계

- **도형 품질은 실행마다 다릅니다.** 도형에서 이번에 바뀐 것은 각도 표시뿐입니다. 도형 윤곽의 모양과 비율은 그대로 제작자에게 달려 있습니다.
- 제작자가 `angle radius`를 직접 적으면 엔진이 호 크기를 맞추지 못해 값이 멀리 놓일 수 있습니다.
- 제작자가 점 표식에 `draw=none`을 빠뜨리면 원본에 없는 호가 함께 그려집니다. 좁은 각에서는 그 호가 커집니다.
- 각 안에 자리가 있는지는 그려진 도형의 모양으로 정해지므로, 모양이 조금 달라지면 같은 값이 각 안에 놓이기도 하고 화살표로 빠지기도 합니다.
- 사람이 두 버전의 출력을 가려 놓고 고르는 비교는 아직 하지 않았습니다.
