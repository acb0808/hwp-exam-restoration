# v2.8.2 변경 내용

v2.8.1 이후의 변경입니다. 문항 안의 도형을 한글 문서에 넣는 방식 하나만 바꿨습니다. 도형이 이제 “글자처럼 취급”으로 들어갑니다. 읽기, 수식, 도형 그리기, 검수, 정답표는 v2.8.1과 같습니다.

수치는 모두 실제로 잰 값입니다. 이미 끝난 복원 작업 하나를 두 버전으로 다시 빌드해 한글에서 내보낸 결과를 비교했고, 모델 호출은 없었습니다.

## 1. 무엇이 바뀌었나

| 영역 | 바뀐 점 |
|---|---|
| 도형을 넣는 방식 | 전에는 도형을 글 앞에 떠 있는 개체로 넣고, 그 아래 문단 간격으로 도형 높이만큼 자리를 잡아 두었습니다. 이제는 도형이 자기 문단의 글자 하나로 들어갑니다(개체 속성의 “글자처럼 취급”, 본문과의 배치 “자리 차지”). 도형이 든 줄이 도형 높이만큼 커집니다 |
| 편집할 때 | 도형을 지우거나 크기를 바꾸면 아래 글이 따라 움직입니다. 전에는 도형의 자리를 문단 간격으로 따로 잡아 두었기 때문에, 도형을 지워도 빈 자리가 남았고 키우면 아래 글과 겹쳤습니다 |
| 도형의 자리 | 전과 같이 단의 왼쪽 끝입니다 |
| 도형 아래 여백 | 도형마다 약 2.8 mm 줄었습니다. 전에는 도형 아래에 빈 줄 하나만큼의 공간이 더 남았습니다 |
| 쪽 배분 추정 | 첫 출력 전에 문항 높이를 어림하는 식을 새 구조에 맞췄습니다 |

## 2. 측정

**끝난 작업 하나를 두 버전으로 다시 빌드 (중학교 시험지 6쪽, 도형 22개, 정답표와 검수 노트 포함)**

| | v2.8.1 | v2.8.2 |
|---|---:|---:|
| 글자처럼 취급인 그림 | 23개 중 1개 | 23개 중 23개 |
| 쪽 수 | 8 | 8 |
| 자리를 넘친 문항 | 0 | 0 |
| 도형이 있는 문항 22개의 내용 높이 | | 문항마다 2.8 ~ 2.9 mm 줄어듦 |
| 도형이 없는 문항 5개의 내용 높이 | | 변화 없음 |

- v2.8.1에서 글자처럼 취급이던 그림 1개는 검수 노트 쪽의 그림입니다. 이 그림은 전부터 그렇게 들어갔습니다.
- 높이 어림식이 예상한 차이는 2.82 mm로, 잰 값과 같습니다.
- 한 시험지로 확인한 결과입니다. 다른 글꼴 크기나 줄 간격의 양식에서는 줄어드는 양이 달라질 수 있습니다.
- 복원에 드는 모델 사용량은 재지 않았습니다. 이번 변경은 문서를 조립하는 코드에만 있고, 제작자와 검수자가 받는 지시나 응답은 그대로입니다.

## 3. 설치와 호환

- 스킬 폴더 전체를 v2.8.2로 교체하고 `hwp-restoration` MCP를 다시 연결하세요. 절차는 [설치 안내](../AGENT_INSTALL.md)의 “이전 버전에서 업데이트할 때”에 있습니다. 첫 `hwp_prepare` 응답의 `runtime_version`이 `2.8.2`여야 합니다.
- v2.8.1에서 올 때 새로 설치할 프로그램이나 Python 패키지는 없습니다. MCP 도구 11개와 서브에이전트 역할 정의의 내용도 그대로입니다. 기존 `.mcp-venv`를 그대로 씁니다.
- 바뀐 파일은 `scripts/question_flow.py`, `scripts/restoration_preplan.py`, `scripts/restoration_fit.py`(주석), `scripts/restoration_single.py`(버전), `tests/test_efficiency.py`와 버전을 적은 문서 두 개입니다.
- 이전 버전으로 만든 작업 폴더를 v2.8.2로 다시 빌드하면 도형이 글자처럼 취급으로 바뀌고 도형 아래 여백이 줄어듭니다. 이미 만든 HWP·HWPX 파일은 바뀌지 않습니다.

## 4. 알려진 한계

- 머리글의 QR 그림은 오른쪽 여백에 놓이도록 전과 같이 떠 있는 개체입니다.
- 도형은 줄 하나를 통째로 차지합니다. 원본에서 도형이 글 옆에 놓인 경우에도 글 아래 줄에 놓이며, 이 점은 v2.8.1과 같습니다.
- 도형 아래 여백이 줄어든 모습이 원본과 더 가까운지는 사람이 두 버전의 출력을 가려 놓고 비교하지 않았습니다.
