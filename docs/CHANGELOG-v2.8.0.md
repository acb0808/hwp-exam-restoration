# v2.8.0 변경 내용

v2.7.9 이후의 변경입니다. 실제 사용 중 나온 문제(칸 넘침, 수식 표기, 도형의 길이 표시, 문항이 많은 교재의 정답표, 그림 없이 글만 필요한 경우)를 고쳤고, 엔진이 모델 호출 없이 처리하는 일을 늘렸습니다.

수치는 모두 실제 실행에서 잰 값이며, 따로 적지 않으면 조건마다 한 번씩 잰 것입니다. 같은 시험지도 실행마다 사용량이 ±2%p쯤 달라집니다.

## 1. 무엇이 바뀌었나

| 영역 | 바뀐 점 |
|---|---|
| 칸 넘침 | 넘칠 문항에는 첫 출력부터 행을 더 주고, 그래도 넘치면 엔진이 한글이 잰 높이로 행 배분을 다시 고릅니다. 모델을 부르지 않습니다. 도형 축소(최대 20%)는 마지막 수단이며 검수 노트에 남깁니다 |
| 수식 | 호 `\overparen{AB}`, 평행 `\parallel`, 도 기호, 단위 앞 간격을 지원합니다. 호인지 각인지 알 수 없는 `\widehat{AB}`는 거절하고 대안을 안내합니다. `×`·`÷`·`≤` 뒤의 `sin`·`log`가 기울어지던 버그를 고쳤습니다 |
| 도형 | 길이 표시 호가 인쇄물처럼 바깥쪽으로 솟습니다. 각 표시 명령 `\ExamAngle`을 추가했습니다. 같은 도형은 두 번까지만 고치고 남은 차이는 검수 노트로 넘깁니다 |
| 도형 검사 | 엔진이 렌더 결과와 원본을 재서 알립니다: 길이 표시 호가 빠짐, 호가 도형 안쪽으로 휨, 길이를 직선 점선 위에 적음, 점선으로 그린 선이 원본에서는 실선임. 원본 쪽에서 도형 영역도 엔진이 다시 찾습니다 |
| 읽기 | 쪽마다 원본 픽셀 크기의 확대 조각 6장을 미리 만들어 제작자에게 줍니다. 윗줄·호·첨자·프라임을 읽기 위한 것입니다 |
| 검수 | 검수자가 새 도구 `hwp_submit_review`로 판정을 직접 제출합니다. 글은 출력 원고와 대조하고, 정답표의 번호·표기는 엔진이 대조합니다. 모든 도형의 원본·출력 대조표가 결과 파일 옆에 저장됩니다 |
| 검수 노트 | 도형 노트에 원본·출력 비교 그림이 들어가고, 노트가 많으면 여러 쪽으로 나눕니다 |
| 정답표 | 문항이 많으면 짧은 답을 한 줄에 네 개씩 놓고, 그래도 넘치면 여러 쪽으로 나눕니다. 단원마다 번호가 다시 시작하는 교재는 번호를 인쇄된 그대로 두고 `원본 1~5쪽` 같은 묶음으로 나눕니다 |
| 텍스트 전용 | `hwp_prepare(include_figures=false)`: 그림 없이 글과 수식만 복원합니다. 기본값은 지금처럼 도형 복원입니다. 사용자가 그림이 필요 없다고 했을 때만 씁니다 |
| Antigravity | 제작자·검수자를 전용 서브에이전트 타입으로 띄워 고정 프롬프트가 약 25,500토큰에서 약 6,000토큰이 됩니다. 한 호출이 120초까지 기다려 상태 조회가 줄어듭니다 |
| 오류 안내 | 거절된 수식 명령마다 대안을 붙입니다. 머리말 값이 비었을 때 어느 값인지 알려 줍니다 |

## 2. 비용

**Antigravity 5시간 한도 (Gemini 3.8 Flash High)**

| 작업 | v2.7.9 | v2.8.0 |
|---|---|---|
| 중학교 시험지 3쪽과 정답표(도형 11개) | 약 8.7%p (v2.7.9 어림식 `1.7 × 쪽 수 + 0.33 × 도형 수`) | 5.2 ~ 6.3%p (전용 타입, 4회) |
| 위와 같음, 전용 타입을 설치하지 않은 경우 | | 7.4 ~ 10.6%p (5회) |
| 유형 교재 10쪽, 텍스트 전용(답 51개) | 지원하지 않음 | 10.6%p, 12.7분 |

- 같은 쪽을 v2.7.9로 직접 잰 값은 없습니다. v2.7.9 열은 그 버전에서 시험지 11종을 13번 재서 만든 어림식입니다.
- 3쪽 실행의 값은 v2.8.0을 만드는 동안 그때그때의 빌드로 잰 것입니다. 전용 타입 없이 잰 5회는 7.8, 7.7, 8.6, 10.6, 7.4%p였고, 가장 높은 10.6%p는 제작자 한 명이 맞게 그린 도형을 세 번 고친 실행입니다. 텍스트 전용 10쪽은 최종 빌드로 쟀습니다.
- 전용 타입의 효과는 고정 프롬프트 몫입니다(1.53%p → 0.61%p). `scripts/install_reader_agent.py`로 두 정의를 설치해야 적용됩니다.
- 5시간 한도는 `3.75 × (캐시 안 된 입력 + 0.1 × 캐시된 입력 + 5 × 출력) ÷ 100만 토큰`(%p)으로 계산됩니다. 여러 실행에서 맞았고, 최근 실행 한 번은 실측이 0.9%p 높았습니다.

**텍스트 전용과 도형 포함 (같은 교재 10쪽, OpenCode)**

| | 도형 포함 | 텍스트 전용 |
|---|---:|---:|
| 가중 토큰 | 597만 | 269만 (−55%) |
| 시간 | 35.9분 | 21.8분 (−39%) |

**OpenCode의 달러 비용은 줄지 않았습니다.** 같은 시험지 세 종에서 $0.134 → $0.151, $0.209 → $0.178, $0.046 → $0.070입니다. 확대 조각만큼 이미지 입력이 늘었기 때문입니다. 호출 수로 사용량을 재는 호스트에서는 아래의 턴 수가 기준입니다.

## 3. 효율

같은 시험지를 v2.7.9와 v2.8.0으로 한 번씩 전체 복원했습니다(OpenCode, 정답표 포함).

| | 시험지 A (중 6쪽) | 시험지 B (중 6쪽, 칸 넘침) | 시험지 C (고 4쪽) |
|---|---|---|---|
| 전체 턴 | 169 → 117 (−31%) | 240 → 137 (−43%) | 70 → 69 |
| 소요 시간 | 23.9분 → 16.3분 | 48.4분 → 18.3분 | 9.8분 → 11.5분 |
| 빌드 횟수 | 2 → 2 | 4 → 2 | 1 → 1 |
| 검수 회차 | 1 → 1 | 2 → 1 | 1 → 1 |
| 확대 요청 자리 | 23 → 10 | 22 → 10 | 7 → 5 |

- 원고는 세 시험지의 16쪽 모두 첫 제출에 통과했습니다.
- 칸이 넘치던 쪽은 이전에 제작자 호출 21~27회가 들었습니다. 지금은 엔진이 행 배분으로 해결하고, 사전 행 배분을 넣은 뒤로는 재조판 없이 첫 출력에 통과했습니다.
- 정답표의 번호·표기는 엔진이 대조하므로 검수자가 표 이미지를 열지 않습니다. 보관된 출력 94건이 모두 확인됐습니다.
- 빌드 완료 응답이 8~12KB에서 3.3~3.7KB가 되어 호스트가 응답을 파일로 넘기지 않습니다.
- 시험지 C처럼 원래 수정이 없던 시험지는 턴 수가 그대로이고, 확대 조각을 읽는 만큼 시간이 조금 늘 수 있습니다.

## 4. 해결한 문제

- **칸 넘침으로 재작업이 반복됨.** 넘친 문항을 엔진이 정확히 찾고 스스로 다시 조판합니다(보관된 실패 출력 12건 모두에서 원인 문항을 짚음).
- **호·평행·도 기호가 잘못 찍히거나 거절됨.** 지원 표기를 늘렸고, 거절할 때는 고칠 표기를 알려 줍니다.
- **길이 표시 호가 빠지거나 안쪽으로 휘거나 직선 점선으로 그려짐.** 제작 규칙과 엔진 측정으로 알리고, 고쳐지지 않은 것은 검수 노트에 남습니다.
- **작은 기호(윗줄, 프라임, 첨자)를 놓침.** 확대 조각으로 한 번에 읽습니다.
- **검수 판정을 메인이 옮겨 적다가 형식 오류가 남.** 검수자가 직접 제출합니다.
- **문항이 많은 교재에서 정답표가 한 쪽을 넘으면 오류가 반복됨.** 실제 실행 한 건은 37분 동안 수정 요청만 되풀이하다 결과물 없이 중단됐습니다. 같은 교재가 지금은 12.7분에 오류 없이 끝납니다(정답표 2쪽).
- **단원마다 번호가 다시 시작하면 번호 중복 오류로 멈춤.** 번호를 바꾸지 않고 정답표를 묶음으로 나눕니다.
- **그림이 필요 없는 작업을 지원하지 않음.** 텍스트 전용 작업을 추가했습니다. 제작자는 도형 단계를 건너뛰고, 검수자는 도형이 없는 것을 문제로 적지 않습니다.
- **OpenCode에서 출력 호출이 15초에 끊김.** 설치 안내의 MCP 설정 예시에서 `"timeout": 15000`을 뺐습니다. OpenCode 1.18에서는 이 값이 도구 호출의 제한 시간으로도 쓰입니다. 이전 안내대로 넣었다면 그 줄을 지우세요.
- **두 쪽의 도형 렌더가 동시에 끝나면 한쪽의 측정 노트가 사라짐.** 고쳤습니다.

## 5. 설치와 호환

- 스킬 폴더 전체를 v2.8.0으로 교체하고 `hwp-restoration` MCP를 다시 연결하세요. 절차는 [설치 안내](../AGENT_INSTALL.md)의 “이전 버전에서 업데이트할 때”에 있습니다. 첫 `hwp_prepare` 응답의 `runtime_version`이 `2.8.0`이어야 합니다.
- Python 패키지 `numpy`가 하나 늘었습니다(선택). `.mcp-venv`에서 `pip install -r requirements-mcp.txt`를 한 번 더 실행하세요. 없어도 동작하고, 엔진이 원본에서 도형을 다시 찾는 기능과 선 종류 읽기만 꺼집니다.
- Antigravity에서는 `scripts/install_mcp_server.py`와 `scripts/install_reader_agent.py`(제작자, 검수자 한 번씩)를 다시 실행하세요.
- MCP 도구가 10개에서 11개가 됩니다(`hwp_submit_review`). `hwp_prepare`에 `include_figures`가 늘었습니다(기본 `true`).
- 같은 원고라도 출력이 달라지는 곳: 길이 표시 호가 더 솟고(길이의 0.08배 → 0.12배), 도 기호가 `DEG`로 출력됩니다.
- 완료 응답에 `figure_check_images`가 늘고, 결과 파일 옆에 `결과이름-도형대조-N쪽.png`가 생깁니다.

## 6. 알려진 한계

- **도형 품질은 실행마다 다릅니다.** 길이 표시 호나 선 종류를 제작자가 놓치는 경우가 남아 있고, 놓친 것은 검수 노트와 도형 대조표로 확인해야 합니다.
- **그림을 읽어야 풀리는 문항의 정답은 사람이 확인해야 합니다.** 한 실행에서 종이 접기 문항 세 개의 답이 틀렸는데 검수자가 잡지 못했습니다. 검수자가 제시하는 고칠 값도 틀릴 수 있습니다.
- 세 쪽 이상으로 나뉘는 정답표는 자동 테스트로만 확인했습니다.
- 전용 서브에이전트 타입이 도형 품질에 주는 영향은 두 번의 실행으로는 가르지 못했습니다.
